# CEX Arbitrage Trading Engine - Architecture & Rules

> [!CAUTION]
> 🚨 **СТРОГОЕ АРХИТЕКТУРНОЕ ПРАВИЛО [ОБЯЗАТЕЛЬНО К ИСПОЛНЕНИЮ]** 🚨
> Никакая логика взаимодействия с биржами (обход багов, костыли для Hedge Mode, расчет fallback-цен для маркет-ордеров) **НЕ ДОЛЖНА ВЫНОСИТЬСЯ ИЗ КОННЕКТОРОВ** (`gate.rs`, `binance.rs` и т.д.) в общие движки (`engine/`). Если какому-то коннектору требуются особые хаки для выполнения приказа, **все делается строго внутри файла этого коннектора**. Менеджеры в `engine/` передают только абстрактные команды коннекторам.

> [!CAUTION]
> 🚨 **СТРОГОЕ ПРАВИЛО: ЗАПРЕТ REST API [ОБЯЗАТЕЛЬНО К ИСПОЛНЕНИЮ]** 🚨
> **REST API ЗАПРЕЩЁН.** Все коннекторы бирж обязаны использовать **ИСКЛЮЧИТЕЛЬНО WebSocket** для всех операций:
> - ✅ Размещение ордеров — **только WS**
> - ✅ Проверка заливки (fetch_order) — **только WS**
> - ✅ Закрытие позиций — **только WS**
> - ✅ Получение баланса/позиций — **только WS**
> - ✅ Получение ордербуков/тикеров — **только WS** (через коллекторы)
> - ❌ `http.get()`, `http.post()` к API бирж — **СТРОГО ЗАПРЕЩЕНЫ** в коннекторах.

## 🏗️ Микросервисы (VPS)

1. **`core-node` (Торговый движок)**
   - **Роль**: Распределенный монолит на Rust, который круглосуточно качает WebSocket потоки ордербуков, вычисляет спреды и оркестрирует торговый цикл.
   - **Архитектура**: Построена на принципах SOLID. Торговый цикл разделен на специализированные менеджеры: `entry_manager`, `exit_manager`, `risk_manager`, `pnl`.
   - **Базы данных**: Читает настройки из `vps-api.db`. Сохраняет сделки, кэши бирж, снапшоты в `real-trader.db`.

2. **`vps-api` (Бэкенд Интерфейса)**
   - **Роль**: Веб-сервер на Rust (Axum), связующее звено между базой данных и дашбордом.
   - **Базы данных**: Эксклюзивно сохраняет настройки профилей в `vps-api.db`. Читает историю торгов из `real-trader.db`.

## 🗄️ Базы данных (SQLite WAL)

Система строго разделена на два файла базы данных, чтобы настройки (UI) и транзакции (Trade Engine) не блокировали друг друга:
- `vps-api.db`: Хранит настройки профилей, пароли юзеров. Владелец записи: `vps-api`.
- `real-trader.db`: Хранит сделки с ордерами, PnL и кэш (`server_cache`). Владелец записи: `core-node`.
