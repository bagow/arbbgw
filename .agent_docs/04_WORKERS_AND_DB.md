# Фоновые Процессы и Базы Данных (Workers & Database)

Система активно использует асинхронные фоновые процессы (workers) для задач, не терпящих задержек в горячем торговом цикле. Все взаимодействие с базами данных строго инкапсулировано через абстракции (паттерн Repository).

## 🛠️ Фоновые Процессы (Workers)

Фоновые процессы находятся в `core-node/src/engine/workers/`. Они запускаются параллельно основному торговому циклу в `main.rs`.

### 1. Market Data Worker (`market_data.rs`)
Отвечает за регулярную загрузку критических метаданных бирж, которые используются сканером и риск-менеджером:
- **Tick Multipliers / Contract Sizes**: Скачивает информацию о размерах контрактов (KuCoin, Gate, Binance) и обновляет `EngineContext`.
- **Trading Rules**: Кэширует минимальные объемы ордеров и шаги цен, чтобы защитить систему от отклонения ордеров биржей (Invalid Quantity).

### 2. Position Sync Worker (`position_sync.rs`)
Критический recovery-контур системы. Отвечает за выявление рассинхронизаций между базой данных `OPEN` сделок и реальным состоянием аккаунта на биржах (например, в случае ликвидаций или закрытия позиций вручную через сайт биржи).
- Каждые несколько секунд сверяет активные сделки в `real-trader.db` с `fetch_positions()` на биржах.
- Если одна нога исчезла: движок **немедленно аварийно закрывает** вторую ногу и переводит сделку в `EXTERNAL_PARTIAL_CLOSE`.
- Если исчезли обе ноги (например, двойной стоп-лосс на сайте биржи): сделка переводится в `CLOSED` с флагом `EXTERNAL_CLOSE`.
- **Внимание**: Этот процесс не генерирует сырые SQL-запросы! Он обязуется вызывать методы абстракции `TradeRepository`.

## 🗄️ Взаимодействие с Базами Данных (TradeRepository)

Архитектура строго запрещает встраивать сырые строковые SQL-запросы (`SELECT`, `UPDATE`) непосредственно в код бизнес-логики (`engine/`, `workers/`). Все транзакции инкапсулированы в модуле `core-node/src/engine/db.rs` (паттерн Repository).

### Изоляция Таблиц (SQLite WAL)
Используются две базы данных в режиме Write-Ahead Logging для предотвращения блокировок:
1. `vps-api.db` — Хранит `trading_profiles`. Читается движком 1 раз в 3-5 секунд.
2. `real-trader.db` — Основная база для движка. Хранит таблицы `trades`, `decision_snapshots`.

### `TradeRepository`
Модуль предоставляет безопасные абстрактные методы:
- `insert_new_entry` / `mark_trade_closed`
- `flush_live_updates` (пакетное обновление PnL в памяти для UI)
- `emergency_close_trade` / `emergency_partial_close_trade` (используется воркером `position_sync`)

> [!IMPORTANT]
> **ПРАВИЛО ДОСТУПА**: Движок и менеджеры должны инициировать экземпляр `TradeRepository::new(db.clone())` и вызывать его методы. Сырые строки SQLite в `cycle.rs` или `workers/` **ЗАПРЕЩЕНЫ**.
