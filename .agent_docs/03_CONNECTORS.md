# Соглашения по Коннекторам (core-node/src/engine/exchanges/)

Вся логика работы с API конкретных бирж изолирована в файлах реализации трейта `ExchangeConnector`. Если вы добавляете новую биржу, вам нужно создать только новый файл (напр. `okx.rs`) и реализовать трейт `ExchangeConnector`.

## Методы ExchangeConnector
- `place_order`: Открывает позицию. Должен принимать `api_timeout_ms` и передавать его в http reqwest `.timeout()`.
- `close_position`: Закрывает позицию. Содержит логику fallbacks, если биржа не поддерживает Market ордера для "reduce-only".
- `trim_position`: Сброс "хвостов" асимметричных ордеров. Делегирует работу к `close_position` в 99% случаев.
- `fetch_order`: Обязательный метод для проверки реального заполнения (fill) ордера. Без него движок не запишет транзакцию в БД.
- `fetch_positions`: Проверка зависших позиций перед чисткой (ghost hunting).

## Важнейшие хаки конкретных бирж (примеры)
* **Gate.io**: 
  - Не позволяет ставить `price = 0.0` для Market Close в старых контрактах. Если `close_position` получает таймаут или неудачу из-за Hedge Mode проблем, `gate.rs` должен сделать fallback-request с агрессивной лимитной ценой (`bid - 10%`), чтобы 100% избавиться от позиции. Установка флага `close: true` для reduce-only.
* **Binance**: 
  - Выдает ошибку 418 (IP Ban), если скачивать свечи слишком часто. Решено через seed_volume 24h miniTicker REST во время старта коллектора.
* **Bybit**:
  - `fetch_order` должен проверять не только открытые ордера, но и endpoint `history` (`/v5/order/history`), так как IOC ордера моментально пропадают из `/v5/order/realtime`.

## Правило "Загрязнения" (Isolation Rule)
НИКОГДА не выносите специфику биржи в `cycle.rs`. `cycle.rs` не должен вызывать `if exchange == "gate" { fallback() }`. `cycle.rs` просто вызывает `conn_a.close_position(...)` и ожидает, что коннектор "сделает всё возможное", чтобы закрыть ордер.
