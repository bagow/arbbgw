# AGENT README: Crypto Arbitrage System Architecture

Этот файл предназначен для ИИ-агентов (и разработчиков), чтобы быстро понять архитектуру проекта, разделение ответственности и потоки данных. 

Система разделена на две основные части: **Cloudflare (Frontend + State)** и **VPS (Торговая логика + Сбор данных)**.

## 🚀 CI/CD & Deployment (New)

Проект настроен на автоматический деплой через **GitHub Actions**.

## 1. Cloudflare (`arb.bagow.com`)

Cloudflare выступает в роли публичного интерфейса, хранилища состояний и API-шлюза. 

- **Frontend (`/public`)**: Статические файлы интерфейса (HTML/JS/CSS). Хостится целиком на Cloudflare Pages/Workers Assets.
  Фронтенд разделен на две основные части:
  - **Scanner (`chart.html`)**: Аналитическая таблица спредов в реальном времени с графиками OHLC (через прокси воркера).
  - **Trading Dashboard (`index.html`)**: Основной торговый интерфейс с поддержкой профилей.
- **Worker (`/src/index.js`)**: Выполняет две задачи: отдает статические файлы фронтенда и проксирует API-запросы **напрямую на VPS** (`92.5.127.87:4000`). База данных D1 больше **не используется**. Cloudflare Tunnel (`api.arb.bagow.com`) больше **не используется** — Worker проксирует по прямому IP.

### Логика фронтенда (Trading):
Весь интерфейс построен вокруг **профилей торговли** (Tabs в нижней части экрана).
- Каждый профиль может быть в режиме **Paper** (🧪) или **Real** (💰).
- Профили привязаны к конкретному аутентифицированному пользователю (через HTTP Basic Auth).
- Внутри каждого профиля есть 4 под-вкладки:
  1. **Dashboard**: Статистика (KPI), Equity Curve, Win/Loss Ratio и PnL по биржам.
  2. **Active Trades**: Таблица текущих открытых позиций с Live PnL и детальной информацией по каждой "ноге" сделки.
  3. **History**: Архив закрытых сделок.
  4. **Settings**: Индивидуальные настройки для конкретного бота (спреды, объемы, плечи, комиссии и т.д.) и кнопка запуска/остановки.

### Мульти-профильная архитектура (Users & Tabs)
Система поддерживает одновременную работу нескольких пользователей с полной изоляцией данных.

#### 1. Уровень Профилей (Пользовательский)
В системе существуют два независимых профиля (**dima** и **sergei**).
- **Автономия:** Профили никак не пересекаются между собой. Они предназначены для одновременной работы двух разных пользователей.
- **Изоляция:** Настройки, история действий и данные одного профиля полностью скрыты от другого.

#### 2. Уровень Табов (Функциональный)
Внутри каждого профиля реализована система вкладок (табов).
- **Независимость параметров:** Каждый таб функционирует как отдельный торговый инстанс со своими уникальными настройками.
- **Цель использования:** Табы созданы для A/B тестирования. Это позволяет запускать разные торговые стратегии параллельно внутри одного профиля, чтобы сравнивать их эффективность и параметры в реальном времени. Каждый таб — это отдельная система с отдельными настройками, по которым открываются сделки.

## 3. VPS (Торговый движок и сборщик)
**Доступ:** `ssh opc@140.238.217.190`

VPS находится в изолированной сети и отвечает за всю логику, API и хранение данных. На VPS запущены следующие ключевые сервисы:

1. **`vps-api` (API Сервис)**:
   - Единоличная точка доступа (разработана на Rust/Axum) для фронтенда и других сервисов.
   - Подключена к локальной SQLite базе `trades.db` в режиме WAL.
   - Обрабатывает HTTP-запросы, проксируемые через Cloudflare Tunnel (`api.arb.bagow.com`).
   
2. **`rust-collector` (Сборщик данных)**:
   - Подключается к WebSocket'ам криптобирж (Binance, Bybit, Kucoin, и т.д.).
   - Рассчитывает спреды и пушит их напрямую в `vps-api` / `paper-trader` по локальной сети.

3. **`paper-trader` (Торговый бот / Симулятор)**:
   - **Синхронизация:** Читает актуальные настройки напрямую из SQLite (`trades.db`). Не делает сетевых запросов.
   - **Логика работы:** Слушает поток данных от `rust-collector`, открывает виртуальные сделки. 
   - **Обратная связь:** Пишет сделки напрямую в `trades.db`. Не имеет сетевых задержек.

4. **`real-trader` (Торговый бот / Реал)**:
   - Аналогично `paper-trader`, работает локально и пишет/читает `trades.db`. (В разработке).

## Ключевые паттерны работы для Агента при внесении изменений:
- **UI / Отображение данных:** Логика лежит в директории `/public`.
- **Изменение API / Базы:** Логика бэкенда лежит в `vps-api`. Cloudflare Worker (`/src/index.js`) используется только как реверс-прокси.
- **Логика входа/выхода из сделок (PnL, Spread Exit):** Лежит на VPS в компоненте `paper-trader`.
- **Проблемы с коннектом к биржам / Сбор стаканов:** Лежат на VPS в компоненте `rust-collector`.
- Когда правите торговую логику или API, нужно деплоить это на `opc@92.5.127.87` (и перезапускать systemd сервисы).
