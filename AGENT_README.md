# AGENT README: Crypto Arbitrage System Architecture (HFT Edition)

Этот файл предназначен для ИИ-агентов, чтобы быстро понять актуальную архитектуру проекта, разделение ответственности и потоки данных.

Система была полностью переработана для достижения минимальных (Zero-Latency) задержек, безопасности ключей, и поддержки одновременной мульти-профильной торговли. Устаревшие микросервисы (`rust-collector`, `paper-trader`, `real-trader`) были полностью удалены и заменены единым высокопроизводительным движком `core-node`.

Система разделена на две основные части: **Cloudflare (Frontend + Edge Security)** и **VPS (Высокочастотный торговый движок + API-сервер)**.

---

## 🚀 CI/CD & Deployment

Проект настроен на автоматический деплой через **GitHub Actions** (`.github/workflows/deploy.yml`).

### Порядок деплоя
При пуше в ветку `main`, пайплайн собирает бинарники (`core-node`, `vps-api`) и отправляет их на Швейцарский VPS по SSH.
Старые дублирующие сервисы (вроде `paper-trader`) автоматически убиваются командой `killall -9` и удаляются из `systemd` во время пайплайна, чтобы не возникало "Ghost-сервисов", читающих старые или хардкодные настройки (такие как объем сделки в 100$).

## 1. Cloudflare (`arb.bagow.com`)
Cloudflare выступает в роли публичного интерфейса, балансировщика и слоя безопасности.
- **Frontend (`/public`)**: Статические файлы интерфейса (HTML/JS/CSS). Хостится целиком на Cloudflare Pages/Workers Assets.
  Фронтенд разделен на:
  - **Scanner (`chart.html`)**: Аналитическая таблица спредов в реальном времени.
  - **Trading Dashboard (`index.html`)**: Основной торговый интерфейс с поддержкой мульти-профилей (вкладок).
- **Worker (`/src/index.js`)**: Выполняет аутентификацию (Basic Auth) и проксирует `/api/*` запросы сквозь Cloudflare Tunnel на VPS. 

---

## 2. Доступ и Мульти-профильная Архитектура (Users & Tabs)
Система защищена через HTTP Basic Auth.
Пользователи `dima` и `sergei` изолированы друг от друга и имеют возможность создавать **неограниченное количество торговых вкладок (профилей)**. 
Каждая вкладка (Profile) — это фактически независимый торговый алгоритм (Paper или Real), который работает со своими уникальными настройками (Take Profit, Trade Volume, Min Spread).

---

## 3. VPS: Zero-Latency Торговый Движок (`core-node`) и `vps-api`
На сервере через `systemd` работают следующие основные сервисы:

### A) `core-node` (Single-Process Архитектура)
Единый CEX-движок арбитража. 
- **In-Memory Архитектура (`Arc<DashMap>`)**: `collector` внутри `core-node` собирает OrderBook/Tickers по WebSocket (Gate, HTX, KuCoin, Binance, Bybit, Mexc, OKX, Bitget) и сохраняет их в оперативную память.
- **Движок (`engine::paper` и `engine::real`)**: В бесконечном цикле (на каждый "тик" цены) `core-node` перебирает **ВСЕ** активные торговые профили (paper и real), читая их настройки из базы. Для каждого профиля с его личными настройками (в т.ч. `trade_volume`) вычисляются спреды и немедленно принимаются решения.
- **Single Source of Truth**: `core-node` является единственным процессом, имеющим право открывать новые трейды и закрывать их. Это решает проблему коллизий "Ghost-сервисов" и старых настроек.

### B) `vps-api` (Порт 3000)
Бэкенд инфраструктуры для UI.
- Отвечает за коммуникацию с Фронтендом (Cloudflare Worker -> Tunnel -> `vps-api`): отдает/сохраняет настройки профилей, статистику, исторические трейды.
- Обновляет SQLite напрямую, откуда `core-node` (каждые 3 секунды через `settings_refresher`) считывает новые параметры для торговли в Hot Path.

### C) `cloudflared.service`
Создает туннель между Cloudflare Edge и `vps-api`. Сервер закрыт для входящих HTTP-подключений напрямую, защищая от DDoS-атак.

## 4. Базы Данных SQLite (В режиме WAL)
SQLite разделена на три физически разных файла для изоляции дисковых локов:

1. **`/home/opc/core-node/vps-api.db`**: Содержит профили с настройками UI (`trading_profiles`) и кэш (`server_cache`). 
2. **`/home/opc/core-node/paper-trader.db`**: Таблица `trades` только для виртуальных (бумажных) сделок. При агрессивном трейдинге не блокирует боевые базы.
3. **`/home/opc/core-node/real-trader.db`**: Таблица `trades` для реальных денег. Работает с параметром `PRAGMA synchronous = OFF` для максимальной скорости записи, чтобы не тормозить потоки `engine::real`.

---

## 5. Ключевые файлы для работы:
1. **Торговая / Математическая логика**: Все вычисления спредов, коннекты WebSocket и закрытие виртуальных/реальных сделок находится в `core-node/src/` (`spreads.rs`, `engine/paper.rs`, `engine/real.rs`).
2. **API Эндпоинты**: Логика сохранения настроек (сохранение `trade_volume` и т.д.) и выдачи истории находится в `vps-api/src/routes.rs`.
3. **UI / Фронтенд**: Основная логика рендера — `public/trading.js`.
4. В `core-node` **НЕЛЬЗЯ** использовать блокирующие синхронные операции или писать тяжеловесную логику в горячем (Hot Path) цикле приема WebSocket сообщений. Обязательно использование `tokio::spawn`!
