# Руководство по развертыванию (Deployment Guide)

> [!WARNING]
> 🚨 **НИЧЕГО НЕ КОМПИЛИРОВАТЬ НА ЛОКАЛКЕ ИЛИ VPS НАПРЯМУЮ** 🚨
> Как указано в системных правилах: "на впс и на локалке только с помощью github ci/cd просто пуш в гит" и "cargo check - запрещен". Любые изменения должны проходить через коммит в GitHub, откуда CI/CD пайплайн соберет бинарники и развернет их.

## Общая инфраструктура

Проект развертывается на Oracle Cloud VPS (Zurich, `140.238.217.190`, юзер `opc`). SSH доступ: `ssh opc@140.238.217.190`.

- **Сборка**: Осуществляется эксклюзивно через GitHub Actions (`ci/cd`).
- **Сетевой уровень**: Входящий трафик проксируется через Cloudflare Tunnel (`cloudflared`), скрывая реальный IP сервера. Наружу порты (такие как 4000) не открываются. Дашборд (React UI) хостится на Cloudflare Pages/Workers, а запросы к API проксируются через туннель к бэкенду `vps-api`.
- **Процессы**: Службы контролируются `systemd` (напр. `core-node.service`, `vps-api.service`).

## CI/CD Workflow (GitHub Actions)

1. Разработчик (или Агент) делает `git push`.
2. GitHub Workflow запускает сборку релизных бинарников (`cargo build --release`).
3. Бинарники `core-node` и `vps-api` копируются по SSH на продакшен-сервер (VPS).
4. CI скрипт перезапускает инстансы:
   ```bash
   sudo systemctl restart vps-api
   sudo systemctl restart core-node
   ```
5. Сервисы подхватывают новые версии бинарников и возобновляют работу.

## Состояние БД
При деплое базы данных (`vps-api.db` и `real-trader.db`) НЕ ПЕРЕЗАПИСЫВАЮТСЯ. Они персистентно хранят пользовательские настройки и статистику сделок. Изменения схемы БД должны осуществляться автоматически при старте сервисов (через функцию `init_db`).
